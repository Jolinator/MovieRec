# Secret examples

This directory contains the environment templates used by GCP deployments. `make secrets-init` copies `server.env.example` to `deploy/gcp/secrets/server.env` and fills `TF_VAR_project_id` from the active `gcloud` project. It also creates missing service `.env` files from the matching examples here; it does not copy values from the root `secrets/` directory or the local-only `secrets-example/` templates. The example sets the default region and zone to `europe-west4` and `europe-west4-b`. If `server.env` already exists, `secrets-init` preserves its region and zone; update them explicitly when moving an existing deployment. TLS and JWT key files are generated in `deploy/gcp/secrets/` and are intentionally not stored as example credentials.

`make secrets-init` creates or reuses these files under the ignored `deploy/gcp/secrets/` directory:

- `jwt-private.pem` and `jwt-public.pem`: the RSA key pair used to sign and verify login tokens.
- `tls/server.key` and `tls/server.crt`: the PostgreSQL TLS key and self-signed certificate.

The separate HTTPS certificate for the public ingress is generated by Ansible during `make k8s-config` and stored in the Kubernetes `movierec-web-tls` Secret.

Keep the generated files in `deploy/gcp/secrets/`. Replacing the JWT key pair invalidates existing login tokens.
